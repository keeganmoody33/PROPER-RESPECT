# 002 - Product Motion

> Updated: 2026-09-16. Follow `000-current-product-thesis.md`.

## Core loop

Authorize sources → collect private evidence → propose products and claims → resolve uncertainty with the person → publish reviewed cards.

The app performs discovery and prepares the review. The person chooses access, settles ambiguity, provides otherwise unavailable context, and controls publication. Manual card entry is a fallback, not the default onboarding burden.

## Immediate sequence

1. Exercise actual supported connections with the owner's verified account.
2. Preserve a dated baseline before correcting proposals.
3. Show original excerpts, acquisition method, attribution scope, and separate event dates.
4. Capture Correct / Incorrect / Incomplete / Unknown verdicts and append corrections.
5. Implement separately authorized, read-only email discovery. Do not label Google sign-in as mailbox access.
6. Extend coverage from observed missing tools and evidence. Keep missing answers unknown.
7. Publish reviewed cards with selected links and per-tool cost visibility.

## Acceptance
The owner's profile answers what the tool is, where it is used, what evidence establishes signup and use, the source's usage period, the person's assessment, cost or labeled estimate, and relevant links. The reviewed result works through a shareable URL, while raw evidence remains private. Record discovery mistakes, interpretation mistakes, evidence gaps, and unsupported fields separately.
