# Codex native startup source evidence — 2026-09-23

Verdict: **native startup remains blocked**. Empty HOME, CODEX_HOME, cwd and an allowlisted environment do not establish an isolation boundary. Source explicitly accesses system configuration and macOS managed preferences outside those directories. Flags can reduce effects but do not stop those reads. No Codex executable or account RPC was executed in this audit; no personal configuration, credential, session or transcript was inspected.

Evidence scope: supplied fresh public clone of OpenAI codex tag `rust-v0.153.4`, commit `3d2ee51ca2d5db578f328aa75e20aa22c0197c9a`. Citations below are repository-relative source paths at that commit; corresponding public URLs use `https://github.com/openai/codex/blob/3d2ee51ca2d5db578f328aa75e20aa22c0197c9a/`. This is source inspection, not a proof that installed machine code is compiled from those source bytes. Parent separately reports public-package/installed digest matching; I did not independently repeat that byte comparison.

## Required proposal boundary

Preparation-only adapter is defensible: pin absolute executable identity and digest without invoking it, construct exact arguments/environment/cwd, test lifecycle using synthetic fixtures, refuse native execution with a fixed diagnostic. Do not present a generic injected process-group runner as an OS sandbox. Descendants can escape a process group/session; process-group kill is cleanup for cooperating process trees, not proof of containment against arbitrary code.

A later native execution proposal must first establish an OS-enforced filesystem/network boundary or independently reviewed alternative that handles `/etc`, CoreFoundation preferences, keychain, executable/package context, dynamic libraries, config-derived paths and subprocesses. Merely inspecting that machine's currently absent files is not a durable guarantee. A genuine account attempt additionally requires explicit authorization for credential source, token refresh and its writes, startup services, allowed endpoints, one account scope, private retained metadata, exact timeout/process cleanup and raw-stream suppression. Fresh empty credentials cannot produce genuine account usage; copying or sharing auth later would be new sensitive work, outside this audit.

Evidence gaps remain deliberate: no live native syscall/network trace, no runtime effect coverage, no reproducible-build/binary-source attestation, no exhaustive transitive audit of every startup dependency. Current source contains sufficient concrete contrary evidence to reject the claim that environment hygiene alone makes native startup isolated. No hosted acceptance or Ora gate is closed by this result.
