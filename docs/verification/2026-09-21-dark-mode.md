## Review and design decisions

Pstack `how` grounded the work in the root layout, credential-dependent provider boundary and existing brand tokens. Three architecture candidates and an independent inherited-model judge selected a React theme provider outside AppProviders. No cross-model validation is claimed.

- **Model the domain:** preference and resolved appearance are distinct types; resolved appearance derives from preference and OS state.
- **Boundary discipline:** allowlist stored input; give Clerk concrete appearance colors; freeze card-local fallback tokens before changing shell tokens.
- **Prove it works:** test bootstrap behavior against runtime policy and inspect the actual built app after the full browser suite.
- **Separate shared state:** one implementation worker owned the coupled source/tests; coordinator owned verification and receipt files.

Independent code review found no blocking state, hydration or Clerk API issue. A suggested card focus-color leak was not reproduced by the focused browser test because existing specificity kept the outline stable. The card-local red token was still frozen to complete the brand boundary. The no-comments review found no deletion candidates, no suppression additions and no MUST KILL flags. Final diff received an unslop/technical-writing pass.
