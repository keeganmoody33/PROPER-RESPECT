  `VERCEL_ORG_ID` or `VERCEL_PROJECT_ID`. A same-named broader secret would

## Steps

### 1. Tag and push

```sh
git fetch origin
git checkout origin/main
git tag -a v0.2.0 -m "v0.2.0"
git push origin v0.2.0
```

The `verify` job refuses a tag whose commit is not on `main`, then runs the
tests, lint and typecheck.

### 2. Approve `backend`

Approve the `backend` job in the Actions run. It runs `npx convex deploy -y`,
then `npx convex env set DEPLOYED_SHA <commit>`. The job's deploy key scopes
both commands to production, so they carry no `--prod`. To set the value by
hand from your own logged-in checkout, add the flag:
`npx convex env set --prod DEPLOYED_SHA <commit>`.
The deploy is additive: new tables and fields, no destructive schema change.

### 3. Run the handle migration (skip if the premise check says it ran)

This moves the published `/keegan` snapshot to `/lecturesfrom` and leaves
`/keegan` as a redirect. It only works after step 2, because the function
arrived with #52.

The migration takes nine arguments (`convex/publicationMigration.ts`). Use the
retained values from "Release gate and operator sequence" in
`docs/verification/2026-09-22-canonical-owner-profile.md` (kept outside Git).
If they are lost, rebuild them:

| Argument | Where it comes from |
|---|---|
| `ownerId` | The owner's `users` row `_id` (Convex dashboard, production, Data, `users`, the row with handle `lecturesfrom`). |
| `expectedSubject` | That row's `authSubject`. |
| `publicationId` | The `publishedProfiles` row with handle `keegan`: its `_id`. |
| `expectedRevision` | That row's current `revision`. |
| `expectedSeedKey` | `keegan` (`convex/seed.ts`). |
| `fromHandle` | `keegan`. |
| `toHandle` | `lecturesfrom`. |
| `expectedProfileHash` | See below. |
| `dryRun` | `true` first, then `false`. |

To compute `expectedProfileHash`, copy that `publishedProfiles` row (or just
its `profile` value) from the dashboard into a local file outside Git, then
run:

```sh
node --experimental-strip-types scripts/migration-profile-hash.mjs /path/outside/git/keegan-row.json
```

It prints the lowercase hex SHA-256 of
`canonicalJson({ ...profile, handle: "keegan" })`, the same value the
migration checks. A test (`src/domain/migration-profile-hash.test.ts`) pins it
to the repo's own `canonicalJson` and `sha256`.

Dry run, then apply:

```sh
npx convex run --prod publicationMigration:moveSeededPublication '{"ownerId":"<ownerId>","expectedSubject":"<authSubject>","publicationId":"<publicationId>","expectedRevision":<revision>,"expectedSeedKey":"keegan","fromHandle":"keegan","toHandle":"lecturesfrom","expectedProfileHash":"<hash>","dryRun":true}'
```

Expect `"status": "ready"` with the right `cardCount`. Then run the same
command with `"dryRun":false` and expect `"status": "migrated"`. A repeat
returns `"already-migrated"` and changes nothing. Keep the command outputs as
the release receipt, outside Git if they include identifiers.

### 4. Approve `frontend`

Approve the `frontend` job. It deploys to Vercel production with the commit and
tag as deployment metadata, then fails unless:

- `proper-respect.com` is an alias of the new deployment, and
- `/`, `/lecturesfrom` and `/sitemap.xml` return 200.

### 5. Verify

```sh
curl -s -o /dev/null -w '%{http_code}\n' https://proper-respect.com/lecturesfrom   # 200
curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' https://proper-respect.com/keegan   # 308 to /lecturesfrom
```

Then sign in as the owner and confirm the collection still shows the four
published cards at `lecturesfrom`.

### 6. If the frontend fails

Roll back with Vercel **Instant Rollback** in the dashboard. On the Hobby plan
it can only go back to the previous production deployment. Keep the additive
backend. **Never reseed, and never run a destructive backend rollback.**

After an Instant Rollback, Vercel stops giving the production domain to new
deployments until one is promoted. The next release must start with
`vercel promote` (see [TEMPLATE.md](TEMPLATE.md)).

### 7. After verifying

Remove `CONVEX_DEPLOY_KEY` from the Vercel project's production variables.
The Vercel build no longer deploys Convex and doesn't need it; the preflight
checks it only when it's present.
